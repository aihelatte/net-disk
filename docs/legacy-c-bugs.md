# 原 C 版网盘必须修复 Bug 基线

## 1. 文档目的

本文记录原 C 版本中会导致崩溃、内存破坏、文件损坏、数据不一致或安全失效的必须修复项。

原 C 版本采用“最小改动修复”策略：保留现有客户端/服务端、`epoll`、线程池、MySQL 和文件传输架构，通过逐项调试重新熟悉项目。C++ 重构不在本文范围内。

## 2. 完成标准

每个 Bug 只有同时满足以下条件才能标记为完成：

- 已定位并记录根因；
- 已添加能够复现问题的测试或操作步骤；
- 修复后复现用例通过；
- 相关正常功能和回归测试通过；
- 必要时使用 ASan、TSan、Valgrind 或压力测试验证；
- 文档中记录修复方案和验证结果。

状态统一使用：`待修复`、`修复中`、`已验证`。

## 3. P0：内存与连接安全

### C-BUG-001：网络长度字段未校验

- **状态：** 待修复
- **位置：** `code/server/main.c`、客户端和服务端的文件传输接收逻辑
- **问题：** 直接信任网络传入的 `length`，随后写入固定大小的栈缓冲区。
- **影响：** 越界写、服务崩溃，严重时可能造成任意代码执行。
- **验收：** 所有协议长度在读取正文前完成上下界校验；同时校验 `state`、`pre_length` 及字段间关系，至少保证 `pre_length <= length <= buffer_size`；非法消息会关闭连接且不影响服务进程。

### C-BUG-002：`netFd` 直接作为固定数组下标

- **状态：** 待修复
- **位置：** `code/server/worker.h`、`code/server/clientQueue.c`、`code/server/login.c`
- **问题：** `client[50]` 和 `index[50]` 使用文件描述符作为下标，但文件描述符不保证小于 50。
- **影响：** 连接增多后发生数组越界和内存破坏。
- **验收：** 连接状态不依赖固定长度的 fd 下标数组，或所有访问都有可靠边界和映射机制；高编号 fd 测试通过。

### C-BUG-003：时间轮链表尾指针悬空

- **状态：** 待修复
- **位置：** `code/server/clientQueue.c` 的 `fdDel`
- **问题：** 删除尾节点后未正确更新 `tail`，后续插入可能访问已释放节点。
- **影响：** Use-After-Free、链表损坏和随机崩溃。
- **验收：** 删除头、中间、尾、唯一节点后链表状态均正确；ASan 测试无 UAF。

### C-BUG-004：`recvn` 无法区分成功、断线和错误

- **状态：** 待修复
- **位置：** `code/client/transFile.c`、`code/server/transFile.c`
- **问题：** 成功和对端提前断开都可能返回 0，且多数调用方忽略返回值继续执行。
- **影响：** 使用不完整数据、死循环、阻塞或后续协议错位。
- **验收：** 返回值能够明确表示成功、EOF、可重试错误和致命错误；所有调用点完整处理结果。

## 4. P0：网络与文件传输正确性

### C-BUG-005：网络和磁盘 I/O 未处理短写与短读

- **状态：** 待修复
- **位置：** 客户端和服务端所有协议、Token、命令、文件传输和摘要计算代码
- **问题：** 多处假设一次 `send`、`recv`、`read` 或 `write` 能完成全部数据传输，也没有一致处理 `EINTR` 等可重试错误。
- **影响：** 高负载或大文件场景下协议错位、文件截断、摘要错误和连接阻塞。
- **验收：** 统一使用可靠的网络和磁盘 I/O 循环；正确处理 EOF、`EINTR`、短写和短读；限速、分段、短写模拟及磁盘写入测试通过。

### C-BUG-006：大文件大小溢出及单次发送错误

- **状态：** 待修复
- **位置：** `code/client/transFile.c`、`code/server/transFile.c`
- **问题：** 使用 32 位 `int` 保存文件大小；大文件分支只调用一次 `send`；续传时发送长度和偏移处理错误。
- **影响：** 2 GiB 以上溢出，1 GiB 以上文件可能截断、越界读取或永久阻塞。
- **验收：** 使用明确的 64 位长度类型和网络字节序；删除“大于 1 GiB 单次发送”的特殊分支，所有文件统一采用有界分块循环传输；全量上传、下载和断点续传校验一致。

### C-BUG-007：零长度文件和打开失败后仍继续执行

- **状态：** 待修复
- **位置：** 客户端和服务端 `Upload`/`Download`
- **问题：** `open` 失败后发送错误标记但没有立即结束；零长度文件仍可能执行长度为 0 的 `mmap`。
- **影响：** 对无效 fd 调用 `fstat`/`mmap`，造成错误、崩溃或协议异常。
- **验收：** 打开失败立即结束当前任务并返回明确错误；零字节文件能够正常上传和下载。

### C-BUG-008：文件名可触发路径穿越

- **状态：** 待修复
- **位置：** 客户端 `upload/download` 路径和服务端 `NetDisk` 路径拼接
- **问题：** 文件名允许 `../`、绝对路径、路径分隔符或特殊名称。
- **影响：** 可读取或覆盖限定目录之外的文件。
- **验收：** 文件名经过规范化和白名单校验；最终路径必须位于指定存储根目录；路径穿越测试全部被拒绝。

## 5. P0：并发与超时

### C-BUG-009：客户端长任务共享可变命令数据

- **状态：** 待修复
- **位置：** `code/client/client.c`、`code/client/taskQueue.c`、`code/client/worker.c`
- **问题：** 队列中保存同一个 `server_t` 指针，主线程会覆盖其中的命令和 Token。
- **影响：** 并发上传下载可能执行错误命令、错误文件或产生数据竞争。
- **验收：** 每个任务拥有独立、生命周期明确的数据副本；TSan 无数据竞争；连续并发命令结果正确。

### C-BUG-010：繁忙状态下超时轮盘不推进

- **状态：** 待修复
- **位置：** `code/server/main.c`
- **问题：** 只有 `epoll_wait` 返回 0 时才推进时间轮；服务持续有事件时，空闲连接可能永不超时。
- **影响：** 超时语义失效，连接和内存资源长期占用。
- **验收：** 超时推进基于单调时钟，不依赖服务器是否完全空闲；超时后服务端主动从 `epoll`、时间轮和连接表中移除并关闭连接；控制连接和数据连接都有超时；持续压力下空闲连接仍能按期关闭，慢连接不会永久占用工作线程。

## 6. P0：数据库、鉴权与输入安全

### C-BUG-011：SQL 注入与 `LIKE` 语义错误

- **状态：** 待修复
- **位置：** `code/server/mysql.c`、`code/server/login.c`
- **问题：** 用户名、目录名、文件名等通过 `sprintf` 拼接 SQL；`LIKE` 中的 `%` 和 `_` 也会改变查询语义。
- **影响：** 数据泄露、越权修改或删除，以及文件查询结果错误。
- **验收：** 所有外部输入使用预编译语句和绑定参数；注入字符及通配符测试不能改变 SQL 结构。

### C-BUG-012：数据库高权限凭据硬编码

- **状态：** 待修复
- **位置：** `code/server/mysql.c`
- **问题：** 数据库账号和口令直接写在源码中，且权限过高。
- **影响：** 源码泄露后数据库失守，也无法安全区分开发和测试环境。
- **验收：** 凭据来自受控配置或环境变量；使用最小权限测试账号；日志不会输出口令。

### C-BUG-013：Token 可预测、自行签发和重放

- **状态：** 待修复
- **位置：** `code/server/login.c`、`code/server/token.c`、`code/client/token.c`
- **问题：** JWT 密钥由固定字符串和用户 ID 生成，并发送给客户端；客户端可自行生成新 Token。
- **影响：** 身份认证边界失效，Token 可被猜测或伪造。
- **验收：** 签名密钥只保存在服务端且使用安全随机值；客户端不能自行签发；过期、伪造和跨用户 Token 均被拒绝。

### C-BUG-014：密码散列可被网络重放

- **状态：** 待修复
- **位置：** 客户端和服务端注册、登录流程
- **问题：** 客户端发送固定密码散列，服务端直接比较；该散列实际上成为可重复使用的登录凭据。
- **影响：** 抓包者无需知道原密码即可重放登录。
- **验收：** 使用 TLS 保护认证通信；客户端提交密码但不提交可复用的固定密码散列，密码散列和比较在服务端完成；重复发送已捕获的旧认证消息不能成功登录。

## 7. P0：元数据与物理文件一致性

### C-BUG-015：上传失败产生脏元数据和半文件

- **状态：** 待修复
- **位置：** `code/server/transFile.c` 及相关 MySQL 操作
- **问题：** 文件传输完成前就写入虚拟文件表和本地文件表，失败后没有回滚或清理。
- **影响：** 数据库显示文件存在，但物理文件缺失、不完整或不可下载。
- **验收：** 上传先写临时状态和临时文件；完成大小/摘要校验后再原子重命名并转换数据库状态；明确文件系统操作与数据库事务之间的失败恢复规则；服务重启后能够恢复或清理未完成任务，不声称数据库事务可以直接覆盖文件系统操作。

### C-BUG-016：同目录同名文件错误复用旧 MD5

- **状态：** 待修复
- **位置：** `code/server/transFile.c` 的上传接收逻辑
- **问题：** 同名虚拟文件已存在时，查询函数会覆盖客户端提交的新 MD5，后续可能错误使用旧文件内容。
- **影响：** 新文件内容丢失、秒传误判或元数据指向错误对象。
- **验收：** 明确定义同名上传策略（拒绝、覆盖或版本化）；不同内容不能静默复用旧 MD5。

### C-BUG-017：目录删除不递归且引用计数不完整

- **状态：** 待修复
- **位置：** `code/server/mysql.c` 的 `del_virtual_file` 及引用计数逻辑
- **问题：** 只删除目录自身和一层直接子项；更深层节点成为孤儿，子文件引用计数没有完整减少。
- **影响：** 数据库残留、空间泄漏、秒传引用数错误。
- **验收：** 任意深度目录可完整删除；所有文件引用数正确更新；引用归零后的物理文件按策略清理。

### C-BUG-018：引用计数更新存在竞争且缺少事务

- **状态：** 待修复
- **位置：** `code/server/mysql.c` 的 `add_link`、`minus_link` 等函数
- **问题：** 先查询再加减并更新，多个线程并发操作时会丢失更新；跨表操作也没有事务。
- **影响：** 引用数错误、误删或永久保留物理文件。
- **验收：** 引用数使用原子 SQL 更新且不得为负；相关跨表操作处于同一事务；补充必要的唯一约束和外键/一致性约束；并发秒传、相同内容并发上传和并发删除测试结果正确。

## 8. P1：错误处理与资源管理

### C-BUG-019：错误路径资源泄漏

- **状态：** 待修复
- **位置：** MySQL 查询、文件传输、Socket 和线程池相关函数
- **问题：** 多处提前返回前没有释放 `MYSQL_RES`、关闭数据库连接、文件或 Socket。
- **影响：** 长时间运行后耗尽连接数、文件描述符或内存。
- **验收：** 所有资源在成功和失败路径都能释放；持续错误请求压力测试下资源数量稳定。

### C-BUG-020：返回值语义错误或缺少返回值

- **状态：** 待修复
- **位置：** `update_user_pwd`、部分 `int` 函数及线程池辅助函数
- **问题：** 部分函数成功后仍返回 `EXIT_FAILURE`，部分声明为 `int` 却没有返回值，调用方还经常忽略错误。
- **影响：** 上层无法判断操作结果，产生未定义行为或继续执行错误流程。
- **验收：** 建立统一错误码约定；先开启 `-Wall -Wextra -Wpedantic -Werror=return-type` 并消除项目源码警告，再评估是否启用全量 `-Werror`；无缺失返回和未处理的关键错误。

## 9. 补充发现的必须修复项

### C-BUG-021：阻塞操作可卡死 `epoll` 主循环

- **状态：** 待修复
- **位置：** `code/server/main.c` 的消息接收、注册登录和短命令处理逻辑
- **问题：** 主线程在收到可读事件后调用阻塞式 `recvn` 等待完整消息，并同步执行多次 MySQL 查询。慢客户端只发送部分消息，或数据库查询变慢时，整个事件循环都会被阻塞。
- **影响：** 单个慢连接或慢查询即可阻塞所有客户端，产生 Slowloris 类拒绝服务，`epoll` 和线程池架构失去意义。
- **验收：** 监听和客户端 Socket 使用非阻塞模式；连接保存增量接收状态，事件循环不等待完整正文；数据库和其他耗时操作不在事件循环中执行；慢速发送和慢查询测试期间其他客户端仍能正常响应。

### C-BUG-022：缺少连接状态机和认证门禁

- **状态：** 待修复
- **位置：** `code/server/main.c` 的命令分派和客户端连接状态管理
- **问题：** 服务端主要依据客户端提供的 `state` 分派命令，没有可靠限制未登录连接只能注册、登录或关闭；断线处理也默认连接已经进入用户队列。
- **影响：** 未认证连接可触发目录、文件或时间轮逻辑，导致越权尝试、非法用户 ID、错误清理和状态破坏。
- **验收：** 每个连接具有明确状态，例如 `CONNECTED`、`AUTHENTICATED`、`CLOSING`；所有消息都校验允许的状态转换；未登录业务命令、重复登录、非法状态值和登录前断线测试均被安全处理。

### C-BUG-023：本地输入、字符串拼接和路径分割可越界

- **状态：** 待修复
- **位置：** `code/client/login.c`、`code/client/client.c`、`code/server/handle.c` 及其他 `strcpy`/`strcat`/`sprintf` 调用点
- **问题：** `scanf("%s")` 没有宽度限制；多处将外部字符串复制到固定缓冲区；路径组件数组固定为 20 个但分割循环没有边界检查。
- **影响：** 客户端或服务端栈溢出、路径解析越界、命令截断和随机崩溃。
- **验收：** 统一规定用户名、命令、文件名、路径总长和路径深度上限；所有输入函数和格式化操作都携带目标容量；超长输入、超深路径、空字段和边界长度测试不会越界。

### C-BUG-024：密码 Salt 可预测且散列被截断

- **状态：** 待修复
- **位置：** `code/server/login.c`、`code/client/login.c`
- **问题：** 注册时反复使用 `srand(time(NULL))` 和 `rand()` 生成 Salt，同一秒注册可能获得相同 Salt；`crypt` 结果只保存和比较前 49 字节。
- **影响：** Salt 可预测、密码散列强度下降、不同散列可能被错误视为相同，也增加离线破解风险。
- **验收：** Salt 来自操作系统安全随机源；保存和比较完整密码散列；密码散列与验证在服务端完成；同一秒批量注册得到不同 Salt，数据库字段不会截断散列。

### C-BUG-025：服务端信任客户端提供的 MD5

- **状态：** 待修复
- **位置：** `code/client/transFile.c`、`code/server/transFile.c`、`code/server/md5Maker.c`
- **问题：** 客户端声明文件 MD5，服务端据此判断秒传和建立映射，但文件接收完成后没有由服务端重新计算并核对摘要；MD5 本身也不适合作为面对不可信客户端的内容身份。
- **影响：** 恶意或错误客户端可污染摘要与物理文件映射、错误触发秒传、覆盖相同摘要对象或让元数据指向错误内容。
- **验收：** 文件先写临时路径，完成后由服务端重新计算摘要和大小；校验通过后才能提交；内容标识升级为 SHA-256 或经明确评估的安全摘要；伪造摘要、摘要不符和相同内容并发上传测试均正确。

### C-BUG-026：协议依赖本机结构布局和字节序

- **状态：** 待修复
- **位置：** 客户端和服务端 `train_t`、`train_state_t` 及所有直接发送整数/结构体的代码
- **问题：** 协议直接发送本机 `int` 和结构体片段，没有固定宽度、网络字节序、协议版本、消息类型范围或统一消息头。
- **影响：** 不同 CPU、编译器或程序版本之间可能解析错误；畸形消息也难以可靠拒绝和演进。
- **验收：** 定义固定宽度、网络字节序和有版本号的协议头；禁止依赖结构体内存布局；未知版本、未知类型、非法组合和跨字节序测试有明确结果。

### C-BUG-027：退出流程和线程停止标志不同步

- **状态：** 待修复
- **位置：** 客户端和服务端 `main.c`、`worker.c`、线程池结构
- **问题：** `exitFlag` 在多个线程间读写但没有完整同步；服务端信号注册代码被注释，退出管道分支实际不可达；退出时也没有完整停止接收、排空任务和释放资源的协议。
- **影响：** 数据竞争、线程无法退出、任务丢失、资源泄漏和服务无法优雅停止。
- **验收：** 停止标志通过互斥量或原子机制同步；服务端可接收明确停止信号；停止接收新连接后按策略完成或取消队列任务；所有线程、Socket、文件和数据库资源均被回收；TSan 和重复启动/停止测试通过。
